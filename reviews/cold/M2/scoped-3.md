## Scope

Some behaviour in the focus diff is not in the spec. First, `state init-lead` (and `preflight --fix`, which calls the same `add_missing`) now writes the last valid block into a recreated MISSIONS.md. The `state init-lead` row still says the file comes "from templates", and "The lease" lists only `state set`, `state next`, `lease take` and `lease release` as the writes that restore the block. `init-lead` also needs no lease, while the paragraph says only the holder or a takeover lead can write lead-owned files until the block is restored. Neither changes the lease. Second, `state get` falls back to the last valid block, with a warning, when the worktree's block doesn't parse, which the spec doesn't mention. It still exits 1 if the file is missing. Third, the commit refusal is specified as "for every session including the holder (exit 1)", but a non-holder gets exit 5 from the lease check first, and the test expects that. Fourth, the deepening fetch uses `--depth=200`, which counts branch commits, not MISSIONS.md commits. In a worktree of a shallow project checkout, it also writes the state branch's boundary into the project's `.git/shallow`. The walk still works because the boundary commit carries MISSIONS.md as it stood then (e2). The " (restores the machine block)" commit-message suffix, the warning lines and the new preflight hint are unspecified but harmless. The commit doesn't touch BUILD-STATE.md, so no decision records the new rules: holder commits checked, lease keys that can't be set, the history walk. They tighten v1's "only room.py edits the block" and don't contradict v1. In tests, `t_unreadable_lease_does_not_block_posting` became `t_no_lease_yet_does_not_block_posting`. `t_broken_block_can_be_repaired` and `t_broken_fence_still_names_the_holder` were replaced by `t_damaged_block_falls_back_to_the_last_valid_one`, `t_superseded_lead_refused_while_the_block_is_damaged`, `t_quoted_lease_line_cannot_decide`, `t_takeover_repairs_a_damaged_block` and `t_commit_cannot_drop_or_break_the_block`. Every damage in them is to the opening fence. `python3 tests/test_room.py` and `python3 tests/test_state.py` both print "all passed".
