## Scope

Beyond the spec, the focus diff makes three behaviour changes without updating m2-room-cli.md, whose only change note covers round 1, or BUILD-STATE.md. First, `state commit` lets lead-owned changes through without the lease whenever the pushed MISSIONS.md is missing or its block can't be parsed, where the spec row says lead-owned changes require the lease (exit 5). Second, `say` and `close` post with a warning when the lease is unreadable, a case the lease-check-on-send rule doesn't cover. Third, `lease take` retries once and returns exit 3 only when another session took the lease, and exit 1 after two lost pushes, where the spec row still says "Exit 3 if another session pushed first". v1's "a lead that loses this race stands down" supports the change, but no decision records it. Any command that opens the state worktree, including `say`, `close`, `lease check` and `preflight`, now moves aside and rebuilds a worktree with no history in common with a recreated branch. The spec has no rebuild rule; R1-12 added one only for broken worktrees. The other changes are internal: the helpers `BlockUnreadable`, `repo_of_url`, `project_toplevel` and `is_stale_state_worktree`, `check_state_dir` now always fetching, and `lease_holder` and preflight relying on that fetch. The tests add a `{hooks}` placeholder and `ONCE` to `pre_push`, a `push_edit` helper and five tests in tests/test_state.py. The commit range also touches BUILD-STATE.md (platform checks 5 and 9, findings G and H) and adds round-2.md; both are docs and outside the focus. Both suites pass at 0236df4 (`tests/test_room.py` and `tests/test_state.py`: "all passed"). During the review, another session committed 4ac0bdc on the branch. It touches only reviews/cold/M2/DISPOSITIONS.md, so room.py and tests/ are the same as at 0236df4. The excluded drafts m3-reviews-gate.md and m4-unattended.md were not read.
