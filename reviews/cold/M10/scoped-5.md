No path merges code that no hold showed: every pass goes through check 3, which is unchanged. These ordering probes ran end to end (logs/s5-b.log) and I left them unreported:
- **Edited and deleted holds between.** A hold between that is edited after the decision to name PR #13, or deleted, lets the clearing decision pass. Both need an edit or delete outside room.py, which has neither.
- **A message edited into a hold.** A `STATUS` between that is edited into a hold after the decision fails closed.
- **Untrusted holds.** An untrusted lead-tagged hold neither blocks nor pairs.
- **Two decisions with one number.** With two DECISION-340s and the first before a re-hold, the first allows, by design.
- **A hold reposted with its number.** With 350, 351, 350 again, then "DECISION-350: superseded by MERGE-HOLD-351", the decision passes, because the repost was the newest when it came. That needs a lead reusing a number against `state next counter`.
- **An edited duplicate.** A duplicate of hold 353, edited after its decision, prints the self-referential `MERGE-HOLD-353 came after MERGE-HOLD-353 and before DECISION-353`. The lead re-holds and recovers.
- **IDs against timestamps.** `hold_between` reads only ids, while `before()` reads ids and times, and GitHub ids grow with creation time. An id between with a later time fails closed. An id after the decision with an earlier time doesn't count, and `before()` wouldn't pair it either.
- **A hold with no number.** `MERGE-HOLD 225` counts and prints `MERGE-HOLD came after … answer MERGE-HOLD`, which fails closed.
